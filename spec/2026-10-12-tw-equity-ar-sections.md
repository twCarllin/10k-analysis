## 1. 實測事實（2026-10-12，`<scratch>/survey4.py`，只讀 `data/cache/tw_equity` 快取的年報文字，101 家約 5.5 分）

### 1.1 現金流量（年報「財務狀況及財務績效之檢討分析」章的「現金流量」節）

- 找到 99/101。未找到：5347、5876。
- 版面（依年報應行記載事項準則）有 3 部分：
  - **表 A 本年度現金流量變動**：一列數字。欄位有兩種寫法：
    - 寫法 1（3653）：期初現金餘額｜營業活動淨現金流量｜投資及籌資活動淨現金流量（或分兩欄）｜匯率影響（選填）｜現金剩餘（不足）數額｜補救措施（投資計畫、理財計畫）。
    - 寫法 2（1216）：期初現金(1)｜營業活動淨現金流量(2)｜全年現金流出量(3)｜現金剩餘 (1)+(2)−(3)｜補救措施。
    - 2330：期初｜營業｜投資｜籌資｜匯率｜現金剩餘｜改善計畫，6 個數字欄。
  - **說明文字**：營業／投資／籌資各一段原因說明，例如「投資活動之現金流出約 11,444 億：主要係用於資本支出」。
  - **表 B 未來一年現金流動性分析**：期初現金｜預計營業淨現金流量｜預計投資及籌資淨現金流量（或全年現金流出量）｜預計現金剩餘（不足）｜補救措施，另有說明文字。部分公司寫「不適用」（2330）。
- **口徑不一**：部分公司填的是**個體**數字，不是合併數字。1216 期初現金 97,737 仟元；2881 是金控母公司的數字。
- **版面干擾**：2330 該頁是左右兩欄，左欄是現金流量，右欄是風險管理文字，同一行文字混在一起。
- 2881 的錨點命中「(2)未來一年現金流動性分析」，表 A 在前一頁或更前面。

### 1.2 重要契約（年報「營運概況」章的「重要契約」節）

- 找到 100/101。未找到：1802。2603 第一次命中在目錄頁（目錄判定漏掉），第二次命中才是正文。
- 版面：5 欄表，欄名是**契約性質｜當事人｜契約起訖日期｜主要內容｜限制條款**。欄序不固定，2317 是「性質｜他方當事人｜起迄日期｜主要內容｜限制條款」。
- 儲存格常有多行，例如當事人有 4 家公司、日期寫成「111.9~預告登記塗銷」。純文字逐列解析會把同一列的儲存格切到不同的行（2317、3653 的樣本都有這個情形）。
- 金控（2881）依子公司分段：「(1) 富邦金控：無」「(2) 富邦人壽」之後才是表格。
- 可以寫「無」。

### 1.3 特別記載事項（年報最後一章）

- 章名「特別記載事項」找到 75/101。未找到的 26 家（例：3653、1301）有子項，但章名不同或章名列沒有單獨成一行。
- 內容是固定的 4 個子項（準則規定），多數寫「無」或「請參閱公開資訊觀測站」：
  1. 關係企業相關資料（多數寫「請參閱公開資訊觀測站…關係企業三書表專區」）
  2. 最近年度及截至年報刊印日止，私募有價證券辦理情形
  3. 其他必要補充說明事項
  4. 發生證券交易法第三十六條第三項第二款所定對股東權益或證券價格有重大影響之事項（部分公司另立一章，例如 2317「柒、對股東權益或證券價格有重大影響之事項」）
- 子項的順序不固定（2454：第 3 項是第三十六條，第 4 項是其他補充）。

## 2. 範圍與設計

### 2.1 新模組 `runtime/tw_equity/ar_sections.py`

輸入：年報 `PdfDoc`。輸出 3 個 dataclass，各有 `to_dict()`。每個結果都有 `status`、`pages`（來源頁碼）。

**status 的值**（三個章節共用）：
- `parsed`：找到章節，且解析出結構化內容。
- `none`：找到章節，內容寫「無」或「不適用」。
- `failed`：找到章節，但解析不出內容。附 `reason`。
- `not_found`：沒找到章節。

#### (a) `CashflowSection`

- `actual`（表 A）：`opening_cash`、`cfo`、`cfi`、`cff`、`cfi_cff`（投資及籌資合計，只有合併欄時填）、`outflow`（「全年現金流出量」寫法時填）、`fx`、`closing_cash`、`remedy_invest`、`remedy_finance`（文字）、`page`。金額單位統一為仟元（依表頭單位換算；單位讀不到 → `failed`）。
- `forecast`（表 B）：同上欄位，另有 `applicable: bool`（寫「不適用」時 False）。
- `explanations`：`{"operating": 原文, "investing": 原文, "financing": 原文}`，分別給實際與預估（`actual_explanations`、`forecast_explanations`）。原文保留，不改寫。
- **表 A 的第 3 種寫法：直式兩年比較表**（2412 實測：列＝年初現金、營業、投資、籌資、匯率、年底現金，欄＝114 年、113 年、增減、比例），取本年度欄。2412 文字層部分亂碼（「斉噟活動」＝營業活動）。
- **只有說明文字、沒有表 A 與表 B**（101 家全量約 9 家，使用者 2026-10-12 裁示）：找到該節且至少有營業／投資／籌資其中一段說明 → `status=parsed`、`actual=None`、`forecast=None`、`arith_ok=None`，只存說明原文。沒有任何說明 → `failed`。
- **只寫「千元／仟元／百萬元」沒有幣別**：視為新台幣（2382；主 flow 裁示 2026-10-12）。
- **沒有表 A**（2317、2881、2886 實測：該節只有現金流量比率表或只有表 B）→ `actual=None`，`arith_ok=None`；有表 B 時 status 仍是 `parsed`。
- **表 A／表 B 判別**（3.4 抽驗：2308 等 8 家把「未來一年」下的表當成表 A）：先看表格上方最近的子標題（行首編號＋關鍵字，或整列就是子標題；句中提到不算）。「未來一年…現金流動性／流量分析」→ 表 B；「本年度／最近年度／最近二（兩）年度…現金流量…變動／分析」→ 表 A；判不出 → 沿用表頭「預計」規則。表頭寫「預計」卻落在表 A 子標題下 → 證據矛盾，沿用表頭規則。同節多張表：每張都判得出才採用子標題判定，任一張判不出 → 全部沿用表頭規則。
- **「流入(出)量」欄**：只在沒有「投資及籌資」合併欄、且投資與籌資欄不齊時才考慮；代入後表 A／表 B 算術成立才當作 outflow，不成立 → 不採用（3702：該欄是含營業的淨變動）。
- **表頭「…淨現金流出量」的投資／籌資欄**：原文正數 → 相減；括號或負號 → 相加（3293）。表頭公式的符號套用到所有有編號的欄（3529）。
- **合併與個體兩組表**（2454 實測：同一節先列「3.1 合併財務報表」再列「3.2 個體財務報表」）：有標「合併」或「及子公司」的組 → 取該組；兩組標題都看不出時取文件順序第一張；`basis_label` 記該組標題原文（無標題 → None）。
- **算術檢查**：`arith_ok`。期初 + 各欄淨流量 (+ 匯率) = 剩餘；「流出量」寫法（主 flow 裁示 2026-10-12）：表頭寫明公式（如「(1)+(2)-(3)」）時依公式代入帶號值（2886 表 B：營業與流出量都帶括號，依公式平衡）；表頭沒有公式時，流出量原文是正數 → 期初 + 營業 − 流出 = 剩餘，原文有括號或負號 → 視為帶號淨流量，期初 + 營業 + 流出 = 剩餘（1301）。表 A、表 B 用同一規則。容差 2 仟元（同三表勾稽）。只檢查表 A；表 B 是預估數，公司填報常不平（3653 實測差 214,583 仟元），只記 `forecast.arith_diff`，不影響 status。
- **口徑判定** `basis`：用表 A 的 `opening_cash` 與 `closing_cash` 比對**合併帳本**的上上年底與上年底現金。帳本來源：全年財報（本期欄＝年底、上期欄＝期初），或半年報資產負債表的上年底欄（只能比對年底；期初無資料時只比年底，並在 `basis_note` 註明）。
  - 可比對的數字全部相差 ≤2 仟元 → `consolidated`。
  - 不符 → `non_consolidated`（附兩個數字）。
  - 沒有合併帳本，或帳本沒有年底現金 → `unknown`。
  - 金控（`uses_fh_schema`）一律比對，不另設規則。

#### (b) `ContractsSection`

- `rows`：每列 `nature`（契約性質）、`parties`（當事人，list）、`period`（起訖日期原文）、`content`（主要內容）、`restrictions`（限制條款）、`entity`（金控子公司名；非金控為 None）、`page`。
- 解析順序：先用 `PdfDoc.tables_of` 的表格（pdfplumber 表格保留儲存格多行），依表頭欄名對欄位；表格取不到時，退回文字列解析。文字列解析只在能確定列邊界時產出 row；不確定 → 該頁計入 `failed`，不猜。
- 跨頁：同一節延續到下一頁時合併。
- 合併儲存格（性質、內容欄空白，當事人、期間、限制有字）：期間完整（起訖兩端有數字，或訖端為「迄今」「至今」）且當事人是完整名稱 → 新列並繼承性質、內容；當事人以尾綴詞起頭或期間以起訖符號結尾 → 續行；其餘 → 該頁 failed（審查 🟡-A，2026-10-12）。
- 合併儲存格（只有性質欄空白）：內容欄有字、期間完整、當事人是完整名稱、限制欄有字 → 新列，只沿用性質（主 flow 補表 2026-10-12，item 3.2）。
- 區塊內有兩個以上新契約起點而沒有空白列分隔 → 該頁 failed（item 3.2，避免把多筆契約併成一列）。
- 合併儲存格形狀、期間完整、當事人以括號起頭（「(原…」殘片或「（株）…」新當事人無法分辨）→ 該頁 failed（審查 Task 3 修正輪 🟡2）。
- 金控：子項標題「(n) <公司名>：無」記成該 entity 的 `none_entities`。

#### (c) `SpecialSection`

- 子項 status 依內文判定（依序）：第一句結尾為「無」「不適用」且第一句 ≤200 字 → `none`（3.4 抽驗：組織圖等多小項揭露無句號、最後一小項寫「無」，2379、6505 等 8 家）（優先於 see_mops，裁示 2026-10-12；例外：第一句本身提到公開資訊觀測站時不適用，2317 實測內文無句號）；提到公開資訊觀測站且內文 ≤600 字 → `see_mops`（長篇實質揭露即使提到觀測站也判 `disclosed`，2330、2412 實測）；內文結尾為「無」「不適用」→ `none`；其他 → `disclosed`。
- `items`：4 個固定 key：`affiliates`、`private_placement`、`other_supplement`、`material_events_36`。每項有 `status`（`none`／`see_mops`／`disclosed`／`not_found`）、`text`（原文）、`page`。
- 錨定：先找章名；沒找到 → 改找子項標題（「私募有價證券辦理情形」「其他必要補充說明事項」「第三十六條第三項第二款」「關係企業相關資料」），在目錄頁之後、連續 ≤3 頁內出現 ≥2 個子項，就認定為該章。
- 第 4 項另立一章（2317）時也要能抓到。
- 沒有章名、走子項退回時，`pages` 取子項實際所在頁的最小到最大頁（3.4 抽驗：2801 原為 p5–114）。

### 2.2 錨點（`doc_anchor.py`）

- （主 flow 裁示 2026-10-12）**不改 `doc_anchor.py`**。三章節由 `ar_sections` 自行定位（跳過目錄頁）；在 `ANNUAL_REPORT_ANCHORS` 加 key 會改變其他章節的終止頁。特別記載事項的子項退回規則寫在 `ar_sections`。

### 2.3 接入 `TablesBundle` 與批次

- `TablesBundle` 加 3 個選填欄位：`ar_cashflow`、`ar_contracts`、`ar_special`（預設 None），以及 `ar_sections_error`（解析例外，`<類型>: <訊息>`）。`to_dict()` 只在非 None 時輸出，raw.json 的既有欄位不改。

- 報告（`report.py`）**不改**。

### 2.4 問答（`qa.py`、`qa_llm.py`、`skills/tw/tw_accounting_qa.md`）

- `topic_pack` 新增 3 個主題（年報有讀到時才加）：
  - `ar:cashflow`（kind `ar_cashflow`）：表 A、表 B 的數字與說明原文、`basis`、`arith_ok`、頁碼。
  - `ar:contracts`（kind `ar_contracts`）：契約列。
  - `ar:special`（kind `ar_special`）：4 個子項。
- 年報的來源：`--llm` 路徑已經讀年報（G3b 的 TTM）。這 3 個主題用同一份年報 `PdfDoc`，不重複讀檔。
- **數字核對**：`verify_topics` 把 `ar:cashflow` 的金額加入可用數字。`ar:contracts`、`ar:special` 的數字（日期、金額原文）不做數字核對，但答案必須附頁碼。
- **口徑提示**：`basis` 是 `non_consolidated` 或 `unknown` 時，模板答案與 LLM 指示都要寫明「年報此節的數字不是合併數字（或無法確認）」，不可與帳本的合併現金流量混在同一句比較。
- 模板答案（不打 API 的路徑）：3 個主題各有 render 函式。
- 特別記載 4 個子項的原文，問答時都只給前 800 字並附頁碼（Q3 原只限「其他必要補充說明」；主 flow 2026-10-12 擴及全部子項：2412 關係企業原文 15,304 字）。
- 年報說明原文中帶單位的數字（例：3653「發行可轉換公司債5,197,445 仟元」）可照抄，核對時視為該主題的可用數字；原文沒有的數字仍擋。
- 模板路徑分流：FCF 問題先走既有 FCF 路徑；其餘依用詞分到 3 個年報主題。用詞取窄（審查 Task 2 🟡1）：「未來一年」須後接「現金流動性／狀況／流量／餘額」、「現金剩餘」後不接「股」；「契約」排除契約負債／資產／成本／收入；「私募」排除私募基金；「關係企業」排除關係企業交易；「重大影響」只認「對股東權益或證券價格有重大影響」「重大影響事項」。章節不可答 → 「年報此節無法解析（原因）」。模板答案結尾一律加「模板答案只回答年報章節；問題中的其他部分請單獨提問或加 --llm」。
- skill 文件（`skills/tw/tw_accounting_qa.md`）補主題說明與口徑規則。

### 2.5 驗收工具 `runtime/tw_equity/ar_acceptance.py`

- `python -m runtime.tw_equity.ar_acceptance --all101`：只讀快取（同 `fs_acceptance` 的 OCR 只讀快取規則），每家輸出 3 個章節的 status、cashflow 的 `arith_ok` 與 `basis`、契約列數、特別記載 4 項的 status。最後一行 `SUMMARY`。
