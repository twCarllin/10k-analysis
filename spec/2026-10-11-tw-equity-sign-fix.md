# Spec：tw-equity 指標與變動歸因的符號修正

- run_id：`2026-10-11-tw-equity-sign-fix`
- 日期：2026-10-11
- 背景：使用者指出 FCF 變動公式的資本支出符號問題，要求全面檢查公式。主 flow 用 101 家實際帳本檢查後，找到下列問題。

## 1. 問題（2026-10-11 檢查結果）

### A. 損益表費用的符號不一致，造成工業公司的淨利／營業利益／毛利變動歸因錯誤（最嚴重）

- 各公司財報的印法不同。85 家工業公司中，下列科目本期印成正數的家數（正數代表費用）：

  | 科目 | 印正數的家數 |
  |---|---|
  | 營業成本 | 49 |
  | 推銷費用 | 47 |
  | 管理費用 | 48 |
  | 研發費用 | 43 |
  | 營業費用合計 | 49 |
  | 所得稅 | 44 |

  其他公司印負數，也就是括號金額。
- 勾稽（`statements.run_cross_checks`）與 TTM（`metrics._h1_normalized` 經 `fy_income.normalize_sign`）都有正規化符號。金控 bridge（`compute_fh_bridges`）也有正規化。
- **工業公司的 H1 bridge（`metrics.compute_bridges` → `_value` → `_ledger_value`）直接用帳本原值相加，沒有正規化。** 所以費用印成正數的公司，費用的變動方向是反的，殘差也很大。實例：

  | 公司 | 淨利變動 | 殘差 |
  |---|---|---|
  | 2330 | +5,213.56 億 | −3,098.44 億 |
  | 2356 | +24.36 億 | −2,522.36 億 |

  殘差超過目標變動 5% 的公司，淨利 bridge 有 57 家，營業利益 bridge 有 51 家。
- 問答層 `qa._gross_topics` 的 `bridge:gross_profit`（營收＋營業成本）也用原值，同樣有錯。毛利率拆解（`bridge:gross_margin`）有取 abs(cogs)，所以沒錯。
- 數字核對擋不住這個錯誤，因為數字確實來自帳本，只是正負號錯了。
- 不受影響：FCF bridge、現金淨變動 bridge 的殘差都是 0。CFO bridge 的殘差大，原因是組成項清單只有 28 項，不是符號問題，不在本 run 範圍。

### B. 有效稅率用 abs(所得稅)

- `effective_tax_rate = abs(income_tax) / pretax_income`。公司有所得稅利益時，結果仍是正的稅率。
- 實例：3481 本期、3532 本期；1301、2002、2344、2408、6505 前期（標題「所得稅費用(利益)」且數值為負）；1326、1802、2337、3105、6446 前期（標題「所得稅(費用)利益」且數值為正）。

### C. 金控信用成本率用 abs(provision)

- `credit_cost = abs(provision) / loans_net`。呆帳費用為迴轉時（2880 前期 +5.48 億），結果仍是正的成本率。

### D. 答案呈現會誤導

- FCF 答案印「資本支出：本期 −108.15，去年同期 −76.42，變動 −31.73」（2454）。讀者會以為資本支出減少，實際上是支出增加 31.73 億，使 FCF 減少 31.73 億。
- bridge 答案中的費用項目有相同的問題。

### E. 折舊列黏了區段名

- 11 家工業公司的現金流量表折舊列沒有對到 `depreciation`，所以 EBITDA、資本支出／折舊是空值。例：

  | 公司 | 折舊列的科目名 |
  |---|---|
  | 2454 | `不影響現金流量之收益費損項目:折舊費用` |
  | 2357 | `不影響現金流量之收益費損項目折舊費用(含投資性不動產及使用權資產)` |
  | 1802 | `折舊費用(含使用權資產)` |
  | 3037 | `折舊費用(含投資性不動產及使用權資產)` |
  | 1216 | `不動產、廠房及設備折舊費用` |
  | 2059 | `折舊` |

## 2. 修法

| 代號 | 修法 |
|---|---|
| A | 工業公司的 bridge 取值時正規化符號（`compute_bridges` 的 get；`qa._gross_topics` 的 bridge:gross_profit 同步）：<br>• 費用類 key（cogs、selling_expenses、admin_expenses、rd_expenses、total_opex、finance_costs）→ −\|v\|<br>• income_tax 依標題括號詞：「(費用)」照原值、「(利益)」取 −v；沒有括號詞時取 −\|v\|，或依同頁 cogs 原值的正負判斷，規則和 `fy_income.normalize_sign` 相同<br>• 收入與損益項（revenue、interest_income、other_income、other_gains_losses、equity_method_share）照原值<br>• 優先重用既有的 `normalize_sign`，必要時擴充它的費用 key，不另寫一套規則 |
| B | 有效稅率改成「正規化後的所得稅取負號 ÷ 稅前淨利 × 100」。所得稅利益時為負值 |
| C | 信用成本率改成 `−provision / loans_net × 100`。提存為正，迴轉為負 |
| D | 答案文字：<br>• FCF 答案中的資本支出，改寫成「本期支出 X、去年同期支出 Y，支出增加（減少）Z 億，使 FCF 減少（增加）Z 億」<br>• bridge 答案中的費用類項目，改寫成「費用增加（減少）Z 億，使〈目標〉減少（增加）Z 億」<br>• 數字仍須通過既有的數字核對（`verify_topics`／`verify_numbers`），所以事實包要提供對應的絕對值字串 |
| E | `depreciation` 補別名，或剝除「不影響現金流量之收益費損項目」前綴，讓上述 11 家對到折舊 |

## 6. 追加裁示（2026-10-11，Task 1 交付後）

Task 1 交付時，1.1 DoD ①（2330 淨利殘差 < 5%）沒有達成，另外發現共用規則的問題。使用者裁示如下。

- **A2 所得稅符號規則**
  - 問題：`fy_income.normalize_sign` 遇到標題沒有括號詞、而且同頁 cogs 原值為正時，所得稅取 −v。3044、6274、2609 的營業成本印正數，所得稅卻印負數（費用），結果費用被判成利益。勾稽用 −|v|，所以勾稽仍通過。TTM 路徑也用這個規則，所以這是既有問題。
  - 修法：標題沒有括號詞時，所得稅的符號改用帳上的實際關係判斷：「本期淨利（或繼續營業單位淨利）− 稅前淨利」。兩者都有值，而且差額的絕對值與所得稅原值的絕對值相符（容差 1 仟元）時，用差額的符號；不相符或缺值時，退回 −|v|。H1 bridge 與 TTM 兩條路徑共用同一規則。
  - DoD：
    - 3044、6274、2609 的所得稅取費用（負值），並有測試。
    - `fy_acceptance` 的輸出與修改前相同；如果有差異，要逐項說明，而且差異只能是本規則造成的更正。
- **A3 淨利 bridge 組成項**
  - 問題：2330 等公司的殘差來自沒有列入組成項的列，不是符號問題。
  - 修法：補常見的營業與業外其他項目的別名，並加入淨利 bridge 組成項：其他營業收益及費損淨額、採用權益法認列之關聯企業損益份額、外幣兌換淨益(損)、其他利益及損失淨額。仍有殘差時，答案一定要列出「未歸類項目 X 億」（屬於 Task 2 的呈現）。
  - 新 DoD（取代原 1.1 DoD ①）：
    - 2330 淨利殘差絕對值小於目標變動的 5%。
    - 全量 signscan 中，殘差仍超過 5% 的公司要逐家分類，說明殘差只來自未歸類的組成項。
    - 費用印負數、而且沒有新組成項列的公司，bridge 結果不變。
